# E2E-Serialisierung und Flake-Risiko 2026-11-12

## Seriell ausgeführte E2E-Tests

Die E2E-Tests in `tests/e2e/` laufen **ausschließlich seriell**:

```javascript
// playwright.config.mjs
fullyParallel: false,
workers: 1,
```

### Warum seriell?

Viele E2E-Spezifikationen testen Multiplayer-Szenarien und starten darin:
- Einen lokalen Server
- Mehrere Spieler-Sessions
- Netzwerk-Echtzeit-Interaktionen

Dazu benötigen sie:
- **Feste Ports**: 5173 (Main), 5174 (Online), usw.
- **Exklusive Server-Prozesse**: Nur ein Server pro Port
- **Koordinierte Sitzungen**: Keine Port-Konflikte

Paralleles Ausführen würde zu Zeitstempels-Kollisionen und falschen Ergebnissen führen.

## Bekannte Flakes

### 1. online-sprung-abwurf.spec.mjs

**Risiko**: Timeout bei langsamer Netzwerk-Performance

```javascript
test('Online-Sprung-Abwurf ohne Zugpause', async ({ page }) => {
  // Test schlägt fehl wenn der WebSocket nicht rechtzeitig antwortet
});
```

**Ursache**: Der Server braucht Zeit für die Verbindungsaufnahme und die
Message-Verarbeitung. Bei verlangsamter Emulation oder hoher CPU-Last
fällt der Timeout von 10s aus.

**Maßnahme**: In CI-Modus (`CI=true`) werden Tests mit `--retries 1` wiederholt.

### 2. profiling.spec.mjs (60-Hz-Budget)

**Risiko**: Frame-Zeit überschreitet 16,67 ms (60 Hz)

```javascript
test('profiling: 60 Hz Frame Budget', async ({ page }) => {
  const frameTime = await page.evaluate(() => window.frameTime);
  expect(frameTime).toBeLessThan(16.67);
});
```

**Ursache**: 
- CI-Runner haben höhere Latenz als lokale Maschinen
- Andere Tests beleben den Prozess vorher
- Browser-Kompatibilitätsunterschiede

**Maßnahme**:
- Timeout-Erweiterung auf 30s in CI
- Relativ statt absolut testen (`toBeLessThan(50)` statt `toBeLessThan(16.67)`)
- CI-spezifische Skipped-Tests

### 3. feuerwesen-fassung20.test.js

**Risiko**: Bildvergleichs-Abstimmung

```javascript
test('Feuerwesen-Sprites stimmen mit Referenzdarstellung überein');
```

**Ursache**: Unterschiede in Font-Rendierung, Anti-Aliasing, GPU-Implementierung
zwischen lokalen Maschinen und CI-Runnern.

**Maßnahme**: Pixel-tolerante Vergleiche (`expect(img).toMatchSnapshot({ threshold: 0.05 })`).

## Retires Konfiguration

```javascript
// playwright.config.mjs
retries: process.env.CI ? 1 : 0,
```

In CI-Modus werden schlappige Tests automatisch einmal neu gestartet.

## Empfohlene Vorgehensweise für neue E2E-Tests

1. **Keine feste Zeitabhängigkeit**: Verwende relative Zeit oder warte auf Events
2. **Saubere Isolate**: Jeder Test startet frischen Server
3. **Port-Bereinigung**: `afterAll` sollte Server-Prozesse beenden
4. **Retry-Logging**: Bei Retries sollte der Grund dokumentiert sein
